ID: BAN-DS-11-0001
Versão: v01
Gabarito proposto: C
O que o comando pede: Identificar a conduta compatível com as finalidades e a validação dos tokens.

RESOLUÇÃO
OIDC acrescenta informações padronizadas sobre autenticação por meio do ID Token. O cliente deve validá-lo, incluindo emissor, audiência e expiração, conforme o fluxo. O Access Token representa autorização para acessar recursos protegidos e deve ser apresentado à API, que verifica o acesso permitido. As duas finalidades não tornam os tokens intercambiáveis.

ANÁLISE INDIVIDUAL DAS ALTERNATIVAS
A) Não atende: inverte as funções. O ID Token informa a autenticação ao cliente; o Access Token é a credencial para os recursos protegidos.
B) Não atende: assinatura válida não substitui as verificações de emissor, audiência e expiração exigidas pelo OIDC Core, seção 3.1.3.7.
C) Atende: associa o ID Token à autenticação e o Access Token ao acesso autorizado à API, preservando as validações de cada contexto.
D) Não atende: tokens emitidos para o mesmo usuário podem ter destinatários e finalidades diferentes; a coincidência do usuário não iguala suas permissões.
E) Não atende: o ID Token é representado como JWT pelo OIDC. A RFC 6749 admite formatos diversos de Access Token, sem impor JWT.
